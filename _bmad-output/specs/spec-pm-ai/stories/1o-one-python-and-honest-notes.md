## Intent

**Problem:** Three things a contributor reads tell them something false.

- **Which Python.** The project says it runs on Python 3.13 or later, but the prompt-injection filter's tests only pass on 3.14. Its recorded fingerprint includes the Unicode tables Python ships, and 3.13 ships older ones, so someone whose setup picks 3.13 gets a failing suite on a clean checkout and no hint why. Nothing pins a version; 3.14 is used here only because uv happened to prefer it.
- **The contributor notes.** `AGENTS.md` says the project is Python 3.13 and that the test suite is "sub-second". It takes about a minute.
- **Three code comments** still describe how pm-ai recorded "I checked" before story 8i changed it. They say a check that found nothing counts as having covered nothing. Since 8i, a check that asked and got an empty answer *is* recorded as having looked. Someone reading these comments on the way to the part that decides a promise was broken would come away believing the opposite of what the code does.

**Approach:** Declare Python 3.14 as the one version the project supports, everywhere the version is stated, and correct the notes and the three comments to match the code as it is now. Nothing pm-ai does changes.

## Boundaries & Constraints

**Always:**
- **One version, stated consistently.** The project's minimum version, the version uv selects, and the version the type checker assumes all say 3.14.
- **Package versions do not move.** Regenerating the lock file may rewrite its version markers but must not change any package's version. If it wants to, stop and ask.
- **Comments describe what the code does now**, including the three cases that still count as "did not check": the request failed, nothing that came back had a readable time, or everything that came back was rejected as unreadable.
- **The full suite passes, with 24 skipped.**

**Ask First:** Any package version change the lock file proposes. Any test that fails only on 3.14 for a reason other than the Unicode fingerprint.

**Never:**
- No change to how pm-ai behaves.
- No hand edit to `SPEC.md`, the architecture document or anything else under `_bmad-output/` that a skill re-renders. The architecture document also says "3.13 (3.14 is the upgrade path)"; that is recorded for a re-derive, not edited here.
- No second fingerprint for older Unicode data, and the fingerprint test is not changed to skip.
- The "encryption is disabled" log entry is its own slice (split out 2026-09-25) and is not touched here.
